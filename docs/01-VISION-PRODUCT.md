# 01 · 产品愿景、边界与需求

**状态：** 产品方向已确认；功能设计待 P1-F0 冻结。**目标区域：** 泰国优先，逐步东南亚与全球。

## 1. 一句话产品

**iDoris Bridge = 让客户自有 LINE/Telegram/WhatsApp 等账号，安全连接客户本地 Agent24/iDoris 或兼容第三方 Agent 的开源通信插件与公网 Relay。**

客户获得的不是一个额外的 AI 聊天 SaaS；而是能够通过其日常 SNS 身份访问自己拥有和控制的 AI Agent。

中心化 SNS 平台普遍要求稳定可达的云端 Webhook/API 服务；普通小店不应为此配置公网 IP、证书、入站端口和全年运维。Bridge 提供这一有限而必要的中心化连接基础设施，Agent/模型/知识库/工具和执行权限仍留在客户侧。

## 2. 已确认的产品原则

| 议题 | 结论 |
|---|---|
| 账号归属 | 客户拥有 OA、Telegram Bot、WhatsApp 商业号码；支持解绑与迁移 |
| AI 归属 | 默认 Agent24，调用客户已有 iDoris 模型体系；兼容其他 Agent Host |
| 模型 | 由现有 Agent/iDoris 体系选择客户本地或已授权外部模型；Bridge 不自行决定上云 |
| 知识库、工具、记忆 | 现有 Agent24/客户环境维护，不在中心 Relay 复制 |
| 中心服务 | 最小化公网入口/队列/投递/凭据验证；官方可托管亦可完全自部署 |
| 开源 | 开源通信协议、Relay、Connector 与基础适配器；兼容现有 Apache-2.0 |
| 商业化 | 收取可选的托管 Relay、可靠性运营、部署/支持费用；不是以模型推理订阅为核心的 SaaS |
| 优先顺序 | LINE → Telegram → 稳定性/多租户 → WhatsApp → 正式开源运营 |

## 3. 客户画像和业务实例

| 客户 | 人数典型范围 | 业务价值 | 初期功能 |
|---|---:|---|---|
| 独立创业者/面包店/个体经营 | 1–3 | 处理泰语咨询、营业时间/菜单、商品预订 | 自有 LINE OA、问答、订单草拟、人类确认 |
| 小企业 | 3–20 | 常见问题、报价、工单、预约、客户通知 | LINE + 内部知识/业务工具 |
| 社区、协会 | 30–100 | 活动报名、群组问答、成员通知 | LINE 群/Telegram 群、角色与群发审批 |
| 中型公司 | 50–100+ | 客服、内部流程、跨渠道接待 | 多 Agent 绑定、审计、配额、运维 |
| 开发者和其他 Agent 厂商 | 不限 | 自主搭建通信渠道而不绑定 Agent24 | 开放 SDK/AgentAdapter、自托管 |

演示纵向流程：顾客对面包店自有 LINE OA 说“今天还有法棍吗？预订两个” → 公网 Relay 投递 → 本地 Agent24 查私有库存知识/工具 → 需要审批时由店主批准 → 从原店铺 OA 回复/通知。不得在模型回话时就擅自向库存系统提交订单。

## 4. 用户体验目标

客户实际感知的是“连接我自己的账号，把它交给我自己的 AI Agent 服务”，不是配置复杂的模型 API：

1. 安装本地 Connector/Agent24 插件并与本地 Agent Host 配对。
2. 在本地向导中选 LINE、Telegram 或其他渠道，按官方流程使用自己的平台账号。
3. 绑定“这个外部 Bot → 我的哪个 Agent / 哪种默认权限”。
4. 发送一条测试消息确认成功，设置人工接管和发送额度预算。
5. 任何时候都能离线、暂停、撤销访问、备份/导出配置或迁移 Relay。

指标建议（不是当前承诺）：首次接入成功率；店主实际完成全流程所需步骤；消息确认投递率；Agent 首响应延迟；离线恢复率；重复工具副作用为零；计费超限发送为零；租户越权为零。

## 5. 不做的事（强边界）

- **不**新建 LLM 模型路由、知识库平台、Agent Loop、记忆系统或通用业务 CRM。
- **不**要求客户把整套 Agent 上传/托管到 iDoris 官方服务器。
- **不**拥有客户 LINE/Telegram/WhatsApp 官方身份，也不收集客户个人 LINE 登录密码。
- **不**对外开放 iDoris Admin API、Agent24 任意管理接口或内网反向代理。
- **不**默认替客户支付消息平台费用；平台费和 Relay 运维费分账。
- **不**承诺第三方 SNS 的端到端加密、永久消息保留、平台外政策豁免或“完全免费推送”。

## 6. 第一版本与长期产品差异

**MVP:** LINE 自有 OA，客户手动完成官方开户/授权，Connector 连 Relay、Agent24 接真实本地模型、问答和一项受控工具操作。**扩展:** Telegram Managed Bot 引导、第三方 Agent 兼容、可自部署、WhatsApp 合规接入、更多渠道、自动化诊断与运营控制台。LINE Module OAuth 是可申请的远期能力，不是 MVP 前置条件。
